# 检查页面，整理交付说明

## 这次要做什么

页面做完后，先让 AI 审查本轮改动，再自己操作一次。最后留下一份简短说明，让同事知道做了什么、验证了什么、还有什么没完成。

## 复制这段提示词

```text:no-line-numbers
请审查本轮订单页面改动，先不要修改代码。
重点检查复制订单号、支付失败快捷筛选、重置和分页是否符合之前的需求。
发现问题时说明位置、触发步骤和影响；没有证据的问题不要当作确定缺陷。
根据实际改动和检查结果，整理完成内容、已验证项和待联调项，未执行的检查如实注明。
```

## 操作后应看到什么

| 你来检查 | 完成标准 |
| --- | --- |
| 在编辑器中查看本轮改动 | 文件与订单页面相关，复用方式符合项目规则 |
| 复制订单号并粘贴 | 得到完整且正确的订单号 |
| 点击失败快捷筛选，再点击重置 | 状态、列表和页码按预期一起更新 |
| 切换页码，打开订单详情 | 列表与页码对应，详情没有串到其他订单 |
| 阅读 AI 的检查结果 | 已通过、失败和未执行的检查分别说明，模拟数据未被写成真实接口联调通过 |

审查发现问题时，先修复，再重复对应操作。把实际结果填进交付说明即可：

- **完成：** 这次实际增加或修复的功能。
- **已验证：** 实际操作过的场景，以及运行过的检查和结果。
- **待联调：** 尚未接入的接口、未运行的检查或仍未解决的问题。

下一次需求也可以这样推进：描述一个具体改动，让 AI 实现，再亲手核对结果。更多写法见[日常协作流程](/guide/workflow)。
