# 让 AI 填写 profile.md，再人工审查

如果初始化时**选择了生成项目档案**，打开 `.ai-code/profile.md`，把下面的提示词复制到当前项目的 AI 对话中，让 AI 根据项目源码补全未填写内容。

如果选择了“暂不创建”，本步可以跳过，直接进入[根据图片生成页面](/tutorial/first-page)。已有档案时，只补缺失项并核对相关入口。

## 复制这段提示词

```text
请根据当前项目的真实源码，补全 .ai-code/profile.md 中未填写的内容。

先读取项目现有协作规则与 .ai-code/profile.md，了解模板的适用范围。
根据待填写项，定向查看 package.json、目录结构、相关路由、代表性页面、
组件、组合式函数（Hook）、请求层、常量字典与主题样式入口。
每项推荐能力都要核对源码和至少一处实际调用，避免无目的地遍历整个仓库。

填写要求：
1. 将“待填写”、占位路径和示例替换为已核实的项目事实，路径相对项目根目录。
2. 写清适用模块、推荐能力的源码入口、一处参考实现，以及可复用部分和边界。
3. 模板中的默认目录、组件名和常量路径也需要核实，不能直接当成当前项目约定。
4. 已有有效内容尽量保留；确认不存在的能力删除对应示例、空行或空章节，
   不为凑齐模板而创建组件、目录或业务代码。
5. 源码无法判断的团队选择标注“待人工确认”，并在回复中逐项说明，不能猜测。
6. 只修改 .ai-code/profile.md，不修改业务代码、生成规则和检查配置。
   不写入密钥、真实用户数据、任务流水或重复的检查命令。

完成后说明补全了哪些内容、主要依据哪些文件，并列出需要我人工审查的条目。
这份档案需要人工 review（审查）后，才能作为后续生成页面的项目依据。
```

## 填完后，记得人工 review（审查）

在编辑器中查看文件差异，逐项核对：

| 审查项 | 核对方式 |
| --- | --- |
| 路径和组件是否真实 | 打开 AI 填写的源码入口与调用方，确认存在且确实在使用 |
| 参考实现是否值得沿用 | 确认不是废弃页面，说明可借鉴的是布局、配置还是状态管理 |
| 复用边界是否准确 | 搜索提交、重置、分页、弹窗等能力是否符合当前组件契约 |
| 模板内容是否清理 | 没有把示例路径当事实，没有残留无意义的占位内容 |
| 团队选择是否确认 | 逐条处理“待人工确认”，修正不符合团队习惯的结论 |

可以使用 Git 查看档案状态和差异；新生成的未跟踪文件需要直接打开审查：

```bash
git status --short -- .ai-code/profile.md
git diff -- .ai-code/profile.md
git diff --cached -- .ai-code/profile.md
```

**完成标志：** 选择生成的 profile 已补全并经过人工审查，与下一步页面有关的待确认项已处理。接着把[参考图和页面提示词](/tutorial/first-page)一起交给 AI。
