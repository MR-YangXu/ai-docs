# 用结果验证这次改动

`front-aggregate` 当前有 ESLint，但没有独立测试脚本。本步使用文件检查与相关行为核对；无需为了完成教程安装测试框架。

## 1. 只检查改动文件

在业务项目根目录执行：

```bash
./node_modules/.bin/eslint src/views/users/index/index.vue
```

没有诊断且退出码为 `0` 才是通过。这里没有独立 SCSS 检查命令，样式通过局部差异和实际布局核对。

::: tip 不要误用全仓命令
`npm run lint -- 路径` 仍会执行脚本中的 `eslint .`，不是仅检查指定文件。`npm run build:ts` 包含类型检查和构建，也不是本次页面改动的默认步骤。
:::

出现问题时，将**命令、位置和相关错误**交给 AI：

```text
这是本次 index.vue 的 ESLint 结果：
【粘贴命令、行号与诊断】
请区分本次新增问题与原有问题，只修本次改动造成的错误。
修复后重跑同一命令一次，保留真实失败或未验证状态。
```

## 2. 核对关键行为

相关路径已经在前面验证过的，复用结果即可；未覆盖的每条核对一次。接口可用时使用浏览器 Network（网络）面板查看请求，避免仅凭标签猜测接口已通过。

| 场景 | 操作与证据 |
| --- | --- |
| 空条件 | 初始回显为空，按钮可用；不会显示“未订阅” |
| 数值 `0` | 选“未订阅”并查询，回显正确，请求仍使用数值 `0` |
| 输入与提交分离 | 修改搜索词但不提交；回显和列表请求保持原条件 |
| 查询回第一页 | 在第 2 页查询，列表请求中的 `page` 为 `1` |
| 重置全部 | 改过搜索、状态和站点后重置；字段回到 `queryFormConfig`，页码为 `1` |
| 仅有未提交输入 | 不查询，直接点击新增按钮；组件 key 递增，从初值重建输入 |
| 两个入口一致 | 原有重置与新增按钮都调用 `resetQuery → reset()` |

`usePageList` 已有请求序号保护，可读代码确认旧响应不会覆盖新结果。本次未改共享 Hook，无需再搭建一套请求并发测试。

## 3. 练习一次“复现 → 修复”

如果 AI 生成了真值判断，给它这个具体反馈：

```text
选择“未订阅”并查询后，接口参数 subscription_status 为 0，回显却没有标签。
预期：0 是有效订阅状态，只有未选择时不显示。
请定位 querySummary 的条件判断，复用 subscriptionStatusOptions 按原类型匹配。
修复后核对空条件、未订阅、订阅中，以及重置恢复空条件。
```

不要为了演示故意往业务分支写入错误；正确实现直接保留。

## 什么时候用 TDD？ {#tdd}

TDD（测试驱动开发）适合已有测试设施下的规则变更、回归缺陷和复杂异步行为：先写能复现问题的行为测试，确认因目标行为失败，再实现并运行相关测试。

例如仓库以后接入组件测试，可覆盖“编辑未提交不会改变标签”“数值 0 显示未订阅”“重置一次请求且回到第一页”。测试应通过用户操作断言可见结果和请求参数，避免只断言函数被调用。当前项目未配置这些测试，不能记录为“自动化测试通过”。

## 保留一份真实记录

```text
静态检查：填写实际命令、退出码及诊断摘要。
行为核对：填写已验证场景，注明来自代码路径还是实际操作。
未验证：填写未执行的类型检查、自动化测试及未联调接口。
```

**完成标志：** 已验证项有证据，缺失的检查没有被写成通过。
